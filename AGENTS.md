# Working agreements

This hactahon notion: https://app.notion.com/p/luxed/Hackathon-Build-for-Impact-403e7bbddae88079adbcdc23eb6a92a3

- Use existing code, tools, and conventions where helpful. Preserve others' work and keep changes focused on the task.
- For branding and interface changes, use [the single approved Here With You design](design/README.md), its four screen references, selected listening-line logo, and shared theme tokens. Earlier checkpoint mockups are history, not alternatives. Apply the same identity to the existing landing and app; do not scaffold another frontend or assume design PNGs publish to Lovable.
- Delegate when it helps. Give agents clear ownership, coordinate shared work, and avoid redundant investigation or validation.
- Validate in proportion to the task and risk. Ground conclusions in evidence; distinguish confirmed behavior, assumptions, and remaining gaps.
- Communicate briefly and clearly. Surface meaningful trade-offs and blockers; finish with the result and any relevant checks or unresolved issues.
- For hackathon planning, delegated work, integration, and demo delivery, use [the hackathon skill](.agents/skills/hackathon/SKILL.md). It applies to both main and worker threads.
- Agents can edit shared requirements and status. The main thread reconciles substantive changes with the high-level PRD and user intent; workers own their assigned outcomes and domain detail.
