# Calm minimal revision — web and mobile

The user requests calmer colours and a much more minimal app, matching the restraint already achieved on web. Airy Sage remains the inspiration. These are visual concepts, not live frontend changes.

## Visual changes

- Warm off-white canvas, green-gray text, one muted sage accent. Remove peach selections and the bright multicolour chart palette.
- Use desaturated eucalyptus, slate, stone, olive, and charcoal for chart series, with dash patterns, markers, and named legend items. Production charts must retain sufficient contrast and provide accessible numeric details; minimalism must not obscure series identity.
- One screen heading, no repeated 'All symptoms' heading, no statistic cards or decorative fills.
- Smaller monochrome provisional logo and compact voice action. Final name and mark remain unselected.

## Web

Keep a quiet Home/Journal sidebar, a thin symptom tab row with All, and one generous graph. Remove the primary context-page list in accordance with the previous simplified-navigation decision. Retain a single recent-note link.

## Phone

Replace the bulky six-chip grid and Add symptom row with one 'All symptoms' dropdown. Opening it exposes All plus the five individual symptoms and symptom management. This preserves individual views and combined tracking while reducing visible controls. The selector must have a visible chevron and an accessible label.

Keep a graph, named legend, one recent-note row, a compact Record a note action, and Home/Journal bottom navigation. Journal is plain daily writing and a short dated list, without symptom score cards. Trends remain reachable from a text link.

## Preserved scope

The All view still overlays five individual severity series: fatigue, nausea, pain, appetite loss, sleep difficulty. Retain the prior five-day example data, shared 0–10 severity scale, missing-data rules, direct voice journal writes, existing authenticated backend and storage, and editable notes. Personal context records are preserved; removing primary navigation is not deletion.

The dropdown is a proposed refinement to the previously requested top-level All selector, not a removal of All. Web keeps visible text tabs. The app shows All symptoms by default and the full choices on demand. No additional app screens or platform implementation are claimed.

Generated image artwork is visual guidance, not an authoritative data plot. Implement charts using actual recorded observations. No deployment, native app build, or live Lovable edit is performed.
